# AOCG AI Офис · Выгрузка в 1С
## Профиль организации и правила выгрузки — универсальная модель
**Код документа:** AOCG-1C-001 · **Версия:** 0.2 · **Дата:** 18.09.2026
**Статус:** утверждено владельцем; реализовано в 1C-22
**Изменение 0.2 (18.09.2026):** умолчание `auto_post_policy` — `never`. Платформа документы НЕ проводит: проведение — бухгалтерское действие в чужом учёте. `when_mapped` и `always` включаются только явным выбором клиента. Основание: решение владельца после приёмки 1C-22, где документ 0000-000010 был создан и проведён автоматически при `when_mapped`.
**Контур:** VII · Финансы / 1С

## 0. Зачем этот документ

Выгрузка авансового отчёта в 1С строилась под бюро АОЦГ: упрощёнка «доходы минус расходы», НДС 5 %, счёт 20.01, контрагент как условие проведения. Приёмка 17.09 показала, что часть этих допущений зашита в код константами. Платформа рассчитана на любого клиента с любым режимом налогообложения — значит, **код не должен знать ни одного бухгалтерского факта о клиенте**. Все такие факты живут в **профиле организации**, который клиент настраивает один раз.

Документ отвечает на три вопроса:

1. Что в документе 1С зависит от режима налогообложения и типа организации — и что нет.
2. Какие поля должен нести профиль организации и правило категории, чтобы этого хватило любому клиенту.
3. Как это ложится на 48 категорий, которые уже есть в приложении.

**Принцип:** платформа не решает бухгалтерские вопросы — она спрашивает их у профиля. Слов «АОЦГ», «26», «УСН» в коде нет.

| Что есть | Где | Как используем |

## 2. Режимы налогообложения РФ и что от них зависит в документе 1С

### 2.1 Матрица режимов

| Код | Режим | Кто | Расходы уменьшают налог? | По каким правилам | Что пишем в строку документа |
|---|---|---|---|---|---|
| `osno` | Общая система | ООО, ИП | Да (прибыль / НДФЛ ИП) | гл. 25 НК; у ИП кассовый метод (ст. 221) | вид расхода — через **статью затрат**; поле «Отражение в УСН» **не пишется** |
| `usn_dr` | УСН «доходы минус расходы» | ООО, ИП | Да | ст. 346.16 — с 2026 перечень открытый (пп. 45), правила гл. 25 | **`ОтражениеВУСН`** по правилу категории |
| `usn_d` | УСН «доходы» | ООО, ИП | Нет | — | `ОтражениеВУСН = НеПринимаются` для всех строк; документ проводится ради бухучёта |
| `ausn` | Автоматизированная УСН | ООО, ИП до 5 чел. | Д−Р: да; Д: нет | расходы ФНС берёт из банка и ККТ; авансовый отчёт в 1С — стандартный | как `usn_dr` / `usn_d` по объекту; НДС не платится |
| `eshn` | Единый сельхозналог | ООО, ИП | Да, кассовый метод | ст. 346.5 | как `usn_dr` (то же поле, та же семантика) — подтвердить на живой базе перед включением |
| `psn` | Патент | только ИП | Нет | — | как `usn_d`; при совмещении с УСН — см. 2.3 |
| `npd` | Самозанятый | физлицо / ИП | Нет | нет сотрудников, нет подотчёта | **выгрузка в 1С недоступна**; профиль не создаётся |

### 2.2 Статус по НДС — отдельная ось, не выводится из режима

С 2026 г. упрощенцы платят НДС при доходе свыше 20 млн ₽ (15 млн в 2027, 10 млн с 2028). Поэтому НДС — отдельное поле профиля с тремя значениями:

| Код | Кто | Входящий НДС из чека | Что делаем со строками |
|---|---|---|---|
| `not_payer` | освобождённые: УСН до 20 млн, АУСН, ПСН, ОСНО с освобождением по ст. 145 | не выделяется | одна строка на чек, `СтавкаНДС = БезНДС`, `СуммаНДС = 0` |
| `included` | УСН на ставках 5 % (20–272,5 млн) или 7 % (272,5–490,5 млн) | **к вычету не принимается, включается в стоимость** | одна строка на чек, `БезНДС`; `НДСВключенВСтоимость = true` |
| `deductible` | ОСНО (22 / 10 / 0 %), УСН на общих ставках | к вычету — **только при счёте-фактуре**; по чеку ККТ без СФ — ни к вычету, ни в расходы (п. 1 ст. 170). Исключение — командировочные по БСО (п. 7 ст. 171) | строки по ставкам НДС из чека, `СуммаНДС` заполнена, `НДСВключенВСтоимость = false`, флаг СФ **не ставится**; 1С спишет НДС по своим правилам |

Следствие для контрагента: он нужен только чтобы зарегистрировать счёт-фактуру. По чеку ККТ счёта-фактуры нет. Поэтому **контрагент не является условием проведения ни в одном режиме**. Подставляется, если ИНН нашёлся однозначно, — как справочная информация.

### 2.3 Совмещение режимов (ИП: УСН + ПСН)

Поле `ОтражениеВУСН` в 1С имеет четыре значения: `Принимаются`, `НеПринимаются`, `Распределяются`, `ВозвратРасхода`. `Распределяются` — для ИП, совмещающих УСН и патент: 1С делит расход пропорционально доходам при закрытии квартала. В профиле — флаг `combines_psn`; при нём правило категории может иметь значение `Распределяются` (по умолчанию — для общих расходов: связь, банк, аренда, ПО). Первая версия: флаг храним, значение допускаем, автоматически не назначаем.

### 2.4 Тип организации: ООО или ИП

На состав документа не влияет. Влияет на: (а) допустимые режимы (ПСН и НПД — только ИП), (б) совмещение (только ИП), (в) кассовый метод у ИП на ОСНО — 1С считает сама. В профиле — поле `legal_form` (`ooo` | `ip`) для валидации режима.

## 3. Что в документе 1С НЕ зависит от режима

- Шапка: дата, организация, физлицо, валюта, склад, ответственный, сумма.
- Строка «Прочее»: вид и реквизиты входящего документа («Кассовый чек», ФД, дата), содержание, сумма.
- **Счёт затрат** — зависит от **учётной политики клиента**, не от режима: услуги — 20.01 или 26; торговля — 44; производство — 20/25/26. Платформа не выбирает — клиент задаёт счёт по умолчанию и, при желании, по категориям.
- **Субконто** — определяются счётом: 26 требует статью затрат; 20.01 — номенклатурную группу, статью, продукцию; 44 — статью. Платформа отправляет **только статью затрат**. Счёт, требующий номенклатурную группу, для выгрузки чеков не подходит — профиль это проверяет при настройке (§ 6).
- **Статья затрат** — обязательна всегда, во всех режимах: для ОСНО она несёт вид расхода НУ, для УСН — аналитику. Без неё 1С подставляет свою, молча (замерено 17.09).

## 4. Ось сопоставления: `tax_kind`, а не категория

У каждой категории уже есть `tax_kind` — вид расхода по 1С. В справочнике статей затрат 1С у каждой статьи есть то же поле — `ВидРасходовНУ`. Это одна и та же шкала.

**Следствие:** сопоставлять надо не 48 категорий с N статьями клиента, а **9 видов расхода** с его статьями. Категория → `tax_kind` (наш словарь, универсальный) → статья затрат клиента (его справочник).

| `tax_kind` (наш) | `ВидРасходовНУ` в 1С | Что это |
|---|---|---|
| `material` | МатериальныеРасходы | канцелярия, расходники, хозтовары, малоценка, спецодежда |
| `other` | ПрочиеРасходы | всё, что принимается без особых правил |
| `travel` | КомандировочныеРасходы | проживание, транспорт, визы в командировке |
| `transport` | ТранспортныеРасходы | **доставка товаров** — в торговле распределяется на остаток (ст. 320). Такси сотрудника сюда **не** относится |
| `entertainment` | ПредставительскиеРасходы | нормируемые 4 % от ФОТ |
| `advertising_normed` | РекламныеРасходыНормируемые | нормируемые 1 % от выручки |
| `taxes` | НалогиИСборы | пошлины, сборы |
| `payroll` | ОплатаТруда | услуги по ГПХ |
| `non_deductible` | НеУчитываемыеВЦеляхНалогообложения | штрафы, личное, подарки, сверхнормативное |

### 4.1 Автоподбор статей при настройке профиля

Платформа читает справочник статей затрат клиента (без `$filter` — целиком, замерено: 21 запись, 12 КБ) и для каждого `tax_kind` ищет статьи с тем же `ВидРасходовНУ`:

- **ровно одна** → подставляется автоматически;
- **несколько** → клиент выбирает из списка (например, «Прочие затраты» и «Услуги комиссионеров» — обе ПрочиеРасходы);
- **ни одной** → клиенту показывается, какую статью завести в 1С и с каким видом расхода. Пока не заведена — категории этого вида не сопоставлены, документы с ними не проводятся (§ 7).

Для АОЦГ по замеру 17.09: `material` → «Списание материалов» или «Малоценное оборудование и запасы» (выбор); `other` → 9 кандидатов (выбор, скорее «Прочие затраты»); `travel` → «Командировочные расходы» (одна); `transport` → «Транспортные расходы» (одна); `taxes` → «Имущественные налоги» (одна); `payroll` → «Оплата труда» и «Оплата труда (ЕНВД)» (выбор); `entertainment`, `advertising_normed`, `non_deductible` → **нет ни одной**, заводит бухгалтер.

### 4.2 Переопределение по категории

Правило по `tax_kind` — умолчание. Для отдельной категории клиент может задать свою статью и свой счёт (например, «Топливо» → статья «Содержание служебного автотранспорта», а не общие «Прочие затраты»). Своих категорий организации это касается так же — у них есть `tax_kind`.

| Поле | Тип | Смысл |
|---|---|---|
| `tax_kind` | enum (9) | наш вид расхода |
| `expense_ref` | text NOT NULL | `Ref_Key` статьи затрат клиента |
| `expense_name` | text | для экрана и журнала |
| `account_code` | text NULL | переопределение счёта для этого вида; NULL → счёт профиля |
| `usn_reflection` | enum | `Принимаются` · `НеПринимаются` · `Распределяются`; умолчание из `tax_kind` (`non_deductible` → `НеПринимаются`, иначе `Принимаются`), хранится явно, правится клиентом |

### 5.3 Переопределение по категории — `org_category_map` (нынешняя `odata_category_map`, переименовать)

Те же поля, что в 5.2, ключ (`org_id`, `category_id`). Строка есть — она главнее правила по `tax_kind`. Строк может не быть вовсе: тогда всё идёт по 5.2.

### 5.4 Порядок разрешения для чека

```
категория чека
  → есть строка в org_category_map?      да → её счёт / статья / признак
  → иначе tax_kind категории
      → есть строка в org_expense_kind_map? да → её статья / признак; счёт = её или профиля
      → иначе                                → «без соответствия» (§ 7)
```

## 7. Правила проведения

Документ **создаётся всегда** (если прошли проверки до записи). **Проводится** — по `auto_post_policy`:

- `never` (**умолчание, решение владельца 18.09.2026**) — всегда черновик; бухгалтер проводит сам. Платформа документы не проводит: проведение меняет учёт клиента, и принимать это решение за него нельзя.
- `when_mapped` — только по явному выбору клиента: проводится, если **у всех чеков отчёта есть соответствие** (по категории или по `tax_kind`). Хотя бы одна категория «без соответствия» → черновик, категории названы в ответе и в журнале.
- `always` — только по явному выбору: проводится даже при отсутствии соответствий; для несопоставленных строк статья не отправляется, 1С подставит свою. **Не рекомендуется**, оставлено для клиентов, которые правят в 1С.

Контрагент, НДС, режим — на проведение **не влияют**. Единственный универсальный блокер — неполнота нашей настройки.

Отказы до записи (без строки в журнале): нет профиля → 409 «профиль не настроен»; нет соответствия физлица → 409; счёт из правила не найден в плане счетов → 409; справочник не прочитался → 503.

## 9. Онбординг клиента — как заполняется профиль

Экран «Организация → Учёт и 1С», шаги мастера:

1. **Форма и режим.** ООО / ИП → режим из допустимых → статус по НДС (подсказка порогов: до 20 млн — не плательщик; 20–272,5 — 5 %; 272,5–490,5 — 7 %; общие ставки — с вычетом).
2. **Подключение к 1С** (путь Ⓐ — OData; путь Ⓑ — расширение; для расширения шаги 3–4 те же, читаются через API).
3. **План счетов.** Платформа читает план счетов клиента, показывает счета затрат (20.01, 25, 26, 44 и др.) с их субконто. Клиент выбирает счёт по умолчанию. Счета с субконто «Номенклатурные группы» помечаются «требует проект — для чеков не подходит».
4. **Статьи затрат.** Автоподбор по `ВидРасходовНУ` (§ 4.1). Где одна — подставлено; где несколько — выбор; где ноль — карточка «заведите в 1С статью с видом …», статус «ждёт».
5. **Проверка.** Сводка: сколько категорий сопоставлено, сколько ждёт статьи, какой счёт. Кнопка «Пробная выгрузка одного отчёта» — только с явным подтверждением.

Всё это — данные профиля. Расширение для пути Ⓑ получает их вместе с отчётом и ничего не хранит в 1С.

## 10. Границы первой версии

- **Нормирование** (4 % ФОТ, 1 % выручки, суточные) считает 1С по виду расхода статьи. Платформа только правильно помечает вид.
- **Счёт-фактура** не регистрируется никогда: по чеку ККТ её нет. Вычет НДС по БСО за командировки (п. 7 ст. 171) — возможное расширение для `deductible`, по умолчанию выключено.
- **Совмещение УСН + ПСН** — `Распределяются` допускается как значение правила, автоматически не назначается.
- **ЕСХН** — включать после пробы на живой базе клиента на ЕСХН; семантика ожидается как у УСН Д−Р.
- **АУСН** — как УСН по объекту; расходы ФНС берёт из банка, авансовый отчёт в 1С нужен для бухучёта.
- **НПД** — выгрузки нет.
- **Номенклатура** в 1С не создаётся; строки идут в «Прочее».
- **Проект / объект** — вне этого контура (решение владельца 17.09: «это чеки и всё»).

## 11. Что меняется в плане 1C-22 относительно ЧЕКПОЙНТА 1 агента

| Было в ЧП1 | Становится |
|---|---|
| профиль: `default_account_code`, `vat_mode` | + `legal_form`, `tax_regime`, `combines_psn`, `auto_post_policy`; CHECK на все |
| правило только по категории (`odata_category_map`, 44 строки seed) | **правило по `tax_kind`** (`org_expense_kind_map`, 9 строк) + переопределение по категории (`org_category_map`, по желанию) |
| seed 44 строк по именам категорий | seed профиля АОЦГ + 6 строк `org_expense_kind_map` (те виды, для которых статья в базе есть); 3 вида ждут статей бухгалтера |
| `ОтражениеВУСН` из правила | из правила **только при `usn_*`/`ausn_*`/`eshn`**; при `osno` не пишется; при `usn_d`/`psn` — `НеПринимаются` |
| контрагент блокирует при `deductible` | контрагент **не блокирует нигде**: без счёта-фактуры вычета нет и с контрагентом |
| дробление по ставкам всегда | только при `deductible` |
| — | автоподбор статей по `ВидРасходовНУ` при настройке — отдельный заход, экран профиля (1C-23) |
| — | сверка `tax_kind` в `categories.json` с § 8 — часть ЧП1 |

Мутации к добавлению: `ОтражениеВУСН` пишется при `osno`; чек дробится при `included`; контрагент блокирует проведение; правило категории не главнее правила `tax_kind`; `non_deductible` уходит как `Принимаются`.
