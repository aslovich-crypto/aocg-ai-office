## 0. Решающий критерий

Сформулирован владельцем 10.08.2026 и **перевешивает цену**:

> «Я не разработчик, и площадка, где надо АДМИНИСТРИРОВАТЬ СЕРВЕР, для меня

Поэтому по каждому пункту здесь не «есть/нет», а ответ на вопрос **что

TLS-сертификат, ведение PostgreSQL, обновления окружения.

## 1. Откуда взяты сведения (метод, чтобы можно было оспорить)

Требование задачи — **по документации провайдеров, а не по поисковой выдаче**.
Выполнено так:

- **Timeweb Cloud и Selectel** — страницы их документации прочитаны
  **из прод-контейнера в США** (`railway ssh` → запрос из кода). Причина:
  с рабочей машины владельца не открывается НИ ОДИН российский сайт — поднят
  VPN, имя домена разрешается, а TLS-рукопожатие обрывается. Поисковая выдача
  использована ТОЛЬКО как указатель на адреса страниц; содержание — со страниц.
- **Yandex Cloud** — из **официального репозитория документации**
  `github.com/yandex-cloud/docs` (ветка `master`, файлы `ru/**`). Причина:
  сайт `yandex.cloud` отвечает капчей «Вы не робот?» на запросы из дата-центра,
  а с машины владельца недоступен вовсе. Репозиторий — тот же первоисточник,
  из которого собирается сайт.
- **Принадлежность адресов** — запрошена у RIPE с рабочей машины.

**Граница метода, названа честно:** цены Yandex Cloud получить не удалось
ни одним из путей (капча на `yandex.cloud/ru/prices`, `cloud.yandex.ru/prices`
и `price-list`; в репозитории документации лежат только правила тарификации,
без чисел). Эта клетка таблицы осталась незакрытой, и подставлять в неё числа
по памяти нельзя.

## 2. Доступность из РФ — проверено, а не предположено (11.08.2026)

Замер сделан **с телефона владельца без VPN**, на публичных файлах, которые
ОБЯЗАНЫ отрисоваться. Проверять корень S3-эндпоинта бессмысленно: там нечего
показывать, и «белый экран» читается как поломка канала, хотя это ответ
«показывать нечего» — первый заход именно так и ошибся.

| Хранилище | Адрес | Сеть (RIPE) | Страна | С телефона без VPN |
| --- | --- | --- | --- | --- |
| `storage.yandexcloud.net` | 213.180.193.243 | AS13238 YANDEX LLC | RU | ✅ файл открылся |
| `s3.timeweb.com` | 217.78.234.243/244 | AS9123 JSC «TIMEWEB» | RU | ✅ файл открылся |
| `s3.ru-1.storage.selcloud.ru` | 92.53.68.16 | AS49505 Selectel Ltd | RU | ✅ файл открылся |

**Вывод, важный для выбора:** зона домена (`.net` / `.com` / `.ru`) к фильтрации
отношения не имеет — решение принимается по адресу и сети назначения, а все три
хранилища сидят в РОССИЙСКИХ сетях. Довод «yandexcloud.net — зарубежный домен,
значит отфильтруют» — рассуждение о названии, а не о канале.

Побочно: `selcdn.ru` и `s3.ru-1.storage.selcloud.ru` разрешаются в ОДИН адрес,
то есть проверка по `selcdn.ru` проверила ровно тот канал, которым пойдёт код.

**Замер из прод-контейнера (США → хранилище), тем же днём:** TLS 1.3 встаёт
со всеми тремя, S3 отвечает XML — Яндекс `200 ListAllMyBucketsResult`,
Timeweb `200` то же, Selectel `403 AccessDenied`. Это доказывает, что перелив
старых фото можно гонять с ТЕКУЩЕГО хостинга ещё до переезда, и не доказывает
ничего про доступность из РФ — её дал только телефон.

## 5. Что из нашего стека не переносится напрямую

Не зависит от выбора площадки (делать в любом случае):

- **фото чеков** лежат в базе строкой base64 → вынести в S3 (№3 и S-40).
  API у всех трёх S3-совместимый, код от площадки не зависит: меняются
  только адрес эндпоинта и ключи;
- **приёмник ошибок** Sentry (ЕС) → российский (S-20);
- **почта** Resend (ЕС) и **OCR** Anthropic (США) переездом НЕ снимаются —
  это трансграничная передача, вопрос к юристу и согласию, а не к хостингу;
- **CORS-whitelist и адреса** — правка `CORS_ORIGINS` и упоминаний Railway
  (чек-лист S-06).

Зависит от площадки:

- **Timeweb** — переносится ближе всего к нынешнему устройству: репозиторий →
  сборка платформой → контейнер, база и S3 рядом. Ничего нового строить не надо.
- **Yandex / Selectel** — появляется НОВЫЙ постоянный кусок работы, которого
  сейчас нет: сборка образа, реестр, выкладка ревизий, и это надо поддерживать
  дальше, а не один раз настроить.

**Часы на переезд, класс C (±100%), моя оценка, а не документация:**
Timeweb ~20–30 ч · Yandex ~35–55 ч · Selectel ~40–70 ч плюс постоянное
администрирование.

## 7. Что из этого следует (без рекомендации)

- Риск «переехали, а фото всё равно не видно» **снят замером**: все три
  хранилища открываются из РФ без VPN.
- По решающему критерию — управляемости — площадки расходятся не в мелочах:
  **у Timeweb автодеплой из репозитория ЕСТЬ**, у двух других его нет,
  и вместо него появляется CI, который придётся строить и обслуживать.
- Timeweb при этом остаётся **контролем, а не фаворитом** (уточнение владельца
  10.08.2026): то, что на нём работает PILX, доказывает ровно одно — российский
  хостинг из пострадавшего в июне списка сегодня жив.
