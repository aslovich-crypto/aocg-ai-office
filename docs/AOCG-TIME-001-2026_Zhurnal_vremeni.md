## 1. Система учёта времени v2 (действующая)

**Уровень 1 — оперативный (трекер).** План и факт по каждой задаче — в `docs/TASKS.md` (колонки «План (класс)» и «Факт»). Факт берётся из отчётов Claude Code по чекпойнтам и вписывается при закрытии задачи тем же коммитом. Пилот — блок FIN-.

**Классы точности плана:** A — прямой прецедент (±20%) · B — похожий прецедент (±50%) · C — новая механика (±100%). Метод оценки: декомпозиция на примитивы × нормо-время; для новых кирпичей — вилка PERT (О+4Р+П)/6. Класс обязан расти по ходу работы (C → B после аудита → A после первого факта).

**Уровень 2 — контрольный (git-прогон, ежемесячно).** Независимая сверка по git-истории обоих репозиториев: кластеризация коммитов в сессии. Не зависит от дисциплины записи. Расхождение с трекером >20% — сигнал деградации оперативного учёта.

**Этот документ** — генерируемая сводка по двум источникам. Руками построчно не ведётся.

## 2. Промпт ежемесячного git-прогона (инструмент уровня 2)

Запускать в любой свободной сессии Claude Code в конце месяца:

```
Разовая аналитика, только чтение, ничего не менять и не коммитить.
Задача: восстановить фактические затраты времени на разработку по git-истории
обоих репозиториев (aocg-ai-office и aocg-ai-office-web).

1. Всего коммитов, первый и последний, число уникальных дней с коммитами.
2. Кластеризация в сессии ПО ОБЪЕДИНЁННОЙ шкале двух репозиториев:
   коммиты с разрывом <40 мин = одна сессия.
   Длительность сессии = last - first + 15 мин. Одиночный коммит = 20 мин.
   Сумма по месяцам и итог.
3. Разбивка по доменам по словам в сообщениях коммитов: чеки/скан/OCR,
   UI/дизайн, категории, безопасность, отчёты (REP), ФНС, auth,
   финансы (FIN), документы/трекер, инфра/CI, прочее. Часы по каждому.
4. Оговорка: это НИЖНЯЯ граница — чаты claude.ai в git не видны.
Формат: компактная таблица + итоговая строка «оценка по git: N часов».
```

## 5. Принципы

1. Факт задачи — из отчёта Claude Code, в трекер, тем же коммитом. Не по памяти.
2. Git-прогон — последний рабочий день месяца, результат — в раздел 3 этого документа новой версией.
3. Расхождение трекера и git >20% за месяц — разбор причин, а не игнор.
4. Нормо-время (раздел 4) пополняется при каждом факте нового примитива.
5. Оценка без класса точности не называется. Класс C — честный ответ, «примерно столько-то» без класса — нет.
